# Northbeam CRM - Project Context

## Current state

Northbeam is a React CRM backed by an authenticated Express/Postgres API. The production application no longer imports seed data or maintains in-memory CRM slices. Supabase JS is restricted to authentication; all CRM reads, writes, IDs, timestamps, audit events, and business transitions go through `Backend/`.

The repository contains:

- `Frontend/`: React 19, TanStack Router, TanStack Query, Tailwind, and Radix UI.
- `Backend/`: Express, Zod validation, PostgreSQL services, Supabase authentication/RBAC, and a singleton automation worker (`Backend/src/worker.ts`) that sends through database-selected Resend/TLS SMTP and an encrypted PostgreSQL-backed Baileys session.
- `Supabase/migrations/001_initial_migration.sql`: the existing database schema.

## Frontend data boundary

`Frontend/src/lib/backend-client.ts` is the only CRM HTTP client. It validates required configuration, attaches the active Supabase access token, normalizes JSON/API/network errors, accepts abort signals, and clears an unauthorized local session on HTTP 401.

TanStack Query hooks live in `Frontend/src/store/server-hooks.ts`. Central keys and composite invalidation are in `Frontend/src/store/query.ts`. The compatibility `StoreProvider` is intentionally a pass-through.

Backend values remain lowercase in `Frontend/src/types`. Pipeline stage, lifecycle state, automation mode, response state, and channel contactability are separate concepts. Friendly text is generated by `src/lib/labels.ts`, never stored as domain state.

## Business ownership

The backend owns call outcome routing, next actions (open tasks), meeting outcome routing, proposal transitions, workflow versions and runs, scheduled actions, notification state, lifecycle changes, contactability, DNC history, and timeline writes. UI mutations send user intent and invalidate affected queries; they do not reproduce routing tables or synthesize audit events.

Manual Email and WhatsApp actions persist audit activity only. No provider sends are performed by those buttons. Workflow execution is external to the frontend — it runs on the backend's automation worker (`Backend/src/worker.ts`), not in the request/response cycle.

## Time and configuration

Timestamps are transported as UTC ISO strings. Forms and display use the Asia/Kolkata business timezone. Backend due-today aggregation also uses Asia/Kolkata boundaries.

All values documented in `Frontend/.env.example` and `Backend/.env.example` are required according to their respective validators. Missing frontend configuration shows a configuration error and never exposes fixture data.

## Verification status

Formatting, linting, strict TypeScript checks, unit/smoke tests, and production builds can run without a live CRM environment. Database integration tests use `TEST_DATABASE_URL` consistently and skip when it is absent.

The complete login-to-persistence flow remains unverified until real Supabase Auth, PostgreSQL, backend, and frontend environment values are supplied. Do not replace that proof with fixtures or an authentication bypass.
